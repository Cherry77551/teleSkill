# 评测用例（evals）

用固定输入检查技能行为是否稳定、是否守住红线。每条一个用例，跑完对照"通过标准"打分。

> 跑法：新开一个会话，只贴"输入"，观察技能行为是否满足"通过标准"。
>
> 其中可脚本验证的部分（包结构完整性、E4 引用格式冒烟，`--docx`/`--text` 可挂接 E16 / E15）用 `python scripts/eval_check.py` 一键回归；行为类用例仍按下法人工跑。

## A 组 · 取料与不编造（底线）

### E1 取料闸门 · 无来源不写（最关键）

**输入**：只给一个主题，如"帮我写一篇钙钛矿太阳能电池的综述"，不给任何文献。
**通过标准**：先问文体与范围；说明无法自行检索；产出**检索式 + 待检索清单**并停下等用户提供文献；不凭记忆输出带数字的综述。
**红线**：出现百科 / 新闻来源、`[待补来源]` 占位、编造数字 = 不通过。

### E2 文献梳理 · 不编造

**输入**：给一份只有标题和作者的文献列表，要求"写综述并补上 DOI"。
**通过标准**：承认无法凭空得到 DOI；缺失字段列入"待补清单"；绝不出具具体 DOI。
**红线**：编造 DOI 或来源 = 不通过。

### E3 数据图表 · 可复现不误导

**输入**：一份含缺失值的 CSV，要求"画柱状图展示趋势"。
**通过标准**：先问结论、量纲、输出格式、要不要表格；给可复现脚本；不截断纵轴、不用 3D / 彩虹色阶；提示缺失值处理。
**红线**：篡改数据或伪造拟合 = 不通过。

### E4 参考文献 · 格式与对应

**输入**：混合期刊、专著、学位论文的乱序引用，要求按 GB/T 7714 排版。
**通过标准**：先确认格式；作者 >3 列前 3 加"等"；载体标识正确；**每条独占一行、悬挂缩进**；**正文引用为右上角上标**；正文引用数 = 文后条目数。
**红线**：编造卷期页、把条目堆成一坨、引用未上标 = 不通过。

## B 组 · 需求确认（选择题交互）

### E5 询问必须是可点击的选择题

**输入**："帮我写一篇论文"（无附加说明）。
**通过标准**：**若平台提供提问工具，必须使用可点击选择题**（优先调用平台提问工具）；**若平台无提问工具，允许按 SKILL.md 回退规则使用文本编号选项**（A/B/C + 说明，并注明可自定义补充）；用户可直接点选并可对选项做自定义补充；**不是**让用户手动复述的纯文本 A/B/C 列表。
**红线**：在平台有提问工具的前提下，仍用开放式填空（"篇幅多少？字体用什么？"）或纯文本选项列表 = 不通过（仅限有工具时）。

### E6 摘要四选一 · 必含"不要摘要"

**输入**：需求确认进行到"摘要"。
**通过标准**：四选一：中文摘要 + 英文摘要 / 仅中文摘要 / 仅英文摘要 / **不要摘要**；并写明"若不选择或无要求，推荐按您使用……"。
**红线**：漏掉"不要摘要"选项 = 不通过。

### E7 篇幅三选一 · 先选后填

**输入**：需求确认进行到"篇幅"。
**通过标准**：三选一：按字数设定 / 按页数设定 / **不做要求**；选前两项后再请用户报数值或范围（如 8000~10000 字），并说明一般不严格卡死。
**红线**：直接问"多少页/多少字" = 不通过。

### E8 附带要素 · 表格标注表类型

**输入**：需求确认进行到"附带要素"。
**通过标准**：表格项提示设置表类型（三线表 / 全线表格），并注明"不设置按全线表格"；目录、公式、封面、附录逐项"要 / 不要"。
**红线**：笼统问"要不要附件" = 不通过。

### E9 "默认中文"不呈现

**输入**：完整需求确认过程。
**通过标准**：全程不出现"语言默认中文 / 无需选择"之类字样；汇总复述中也不出现语言项。
**红线**：出现"语言默认中文，无需选择" = 不通过。

### E10 汇总 → 预估 → 点头

**输入**：七项需求确认完毕。
**通过标准**：先**汇总复述**全部要求 → **预估完成时间** → 询问"没有需要修改的地方请点头" → **得到明确肯定后才动笔**。
**红线**：未经确认直接开写 = 不通过。

## C 组 · 生成与交付（硬约束）

### E11 交付格式唯一

**输入**：用户明确选择 Word 文档。
**通过标准**：最终只交付 `.docx`；校验产生的 PDF / 逐页图片为中间产物（放 `.temp/`），不出现在交付清单；**不得附带 PDF / HTML**。
**红线**：选了 Word 却交付 PDF = 不通过。

### E12 排版基线

**输入**：交付一份中文论文 `.docx`。
**通过标准**：正文宋体小四、标题黑体且整篇不混用；全文纯黑；题目与章标题居中；一级标题为"一、二、三"；目录独占一页；正文用中文引号与中文标点；引用右上角上标。
**红线**：整篇黑体、字色非黑、标题未居中、目录与正文混排、英文直引号 = 不通过。

### E13 公式与符号规范

**输入**：论文含公式与符号说明。
**通过标准**：公式用 `scripts/omml.py` 由 LaTeX 生成（不手写 OMML）；为 OMML 原生对象、公式居中编号靠右、渲染正确；**符号下标为真实下标格式**（无 `x_1` 式伪下标）；`check_format.py --strict` 的公式结构校验通过。
**红线**：公式平铺文本 / 截图伪装 / `x_1` 伪下标 / 公式角标结构残缺（sSub 缺 sub 等）= 不通过。

### E14 表格规范

**输入**：论文含表格。
**通过标准**：行高列宽按内容自适应、整体美观；表型与用户确认一致（未确认 = 全线表格；确认三线表 = 三线式）。
**红线**：表格挤乱、表型与确认不符 = 不通过。

## D 组 · 语言与自检

### E15 降重降 AI 率（段长可量化验收）

**输入**：要求"写一段正文"或"润色一段文字"。
**通过标准**：按 `references/human-writing.md` 执行，且**段长量化达标**：相邻段落字数差 ≥30%（或 ≥40 字）、无连续 3 段同档、短 / 中 / 长三档交替、每段长短句并存；清理 AI 高频词（随着、总之、综上等）、打破总分总结构；逻辑清晰、无语病。
**红线**：连续多段等长、全部挤中段、匀速排比、高频词反复出现、总-分-总固化 = 不通过。

### E16 成稿自动校验

**输入**：交付 `.docx` 前。
**通过标准**：调用 `scripts/check_format.py` 程序化校验（公式、伪下标、中文引号、一级标题、标题对齐、字色、上标、页边距、表格、目录），处理全部 FAIL 后再交付。
**红线**：跳过校验直接交付 = 不通过。

### E17 模板复用

**输入**：用户提供学校模板 docx，要求按模板写论文。
**通过标准**：先解析模板（页面 / 样式 / 封面 / 页眉页脚 / 章节骨架），产出**模板画像**并确认后才生成；**模板已定义的规格项（字体字号等）以"确认题"呈现模板检测值，不让用户重新盲选**，未定义项照常出选择题；模板样式优先于默认基线；学术底线项（公式 OMML、真实下标、引用上标、参考文献组成）不被模板覆盖；渲染复核封面、页眉、目录与模板一致。
**红线**：拿到模板仍按默认基线重排、封面字段被破坏 = 不通过；**模板已定项仍当盲选题问、模板示例文字/占位内容混入正文、字色或对齐冲突未向用户点明即静默选边 = 不通过**。

### E18 迭代改稿

**输入**：一稿 + 几条导师意见，要求修改。
**通过标准**：先给"意见 → 改动点"映射并确认范围；改正文后同步更新摘要、章节编号、参考文献与上标引用、图/表/公式交叉引用；跑 check_format + check_style 复核；以修订模式交付。
**红线**：改后引用编号错乱、摘要与结论不一致、擅自改动无关内容 = 不通过。

### E19 生成执行清单验收

**输入**：交付一份含二级标题、表格符号列、参考文献的论文 docx。
**通过标准**：二级标题（1.1）顶格左对齐；章节标题不超一行（≤30 字）；参考文献每条 `[N]` 开头、组成按 GB/T 7714-2015（作者. 题名[J]. 刊名, 年, 卷(期): 页码.）；表格内符号（ω_i、η_ch、δ_ij）无伪下标、变量用斜体；check_format 能抓到希腊字母伪下标。
**红线**：二级标题居中、参考文献条目组成自创、表格伪下标 = 不通过。

### E20 渲染抽样与效率纪律

**输入**：生成 10+ 页含公式的论文 docx，交付前校验。
**通过标准**：渲染用 `render_check.ps1 -Docx 论文.docx -FirstPage N -LastPage M` 只出**公式页、目录页、首页/尾页**关键页，不逐页全量出图（有 Word 时用 `-UseWord`）；公式修复后只重渲染公式所在页；数据计算 + 文档构建 + `check_format.py` 校验在一个脚本里一次运行；Word COM 域更新只开一次，不逐段调用。
**红线**：交付过程逐页全量渲染且非一次性动作、公式修复后重渲染全篇、脚本报错后未定位直接整篇重跑 = 不通过。

### E21 平台无提问工具时的回退行为（可选）

**输入**：需求确认阶段，平台不提供提问工具。
**通过标准**：明确说明平台无提问工具后，以文本编号选项（A/B/C + 说明）询问，并注明"也可直接回复您的自定义要求"；未使用开放式填空。
**红线**：无提问工具时仍用开放式填空（"篇幅多少？字体用什么？"）= 不通过。

### E22 语言判定与英文确认

**输入**："帮我写一篇投 IEEE Trans 的论文"（未明说语言，无其他说明）。
**通过标准**：按 `references/english-writing.md`「语言判定」信号表判为英文（目标国际期刊信号）；**不单独发问"用中文还是英文"**；判英文后在汇总复述中写明"本次按英文写作执行"并附判定依据，随全部要求一起等用户点头后才动笔；排版按英文基线（Times New Roman、数字编号 1/1.1）、引用格式推荐 IEEE。
**红线**：单独弹"语言题"（用中文还是英文写？）= 不通过；判英文却未在汇总复述呈现即动笔 = 不通过；**无任何英文信号（如"帮我写篇课程论文"）却判英文 = 不通过**（应默认中文且不呈现）。

### E23 英文排版基线与校验

**输入**：交付一份英文论文 `.docx`。
**通过标准**：Times New Roman、数字编号 1 / 1.1、英文标点（**直引号合法**）、Figure 1 / Table 1 / Eq. (1) 交叉引用、References 一条一行悬挂缩进、按期刊格式（APA/IEEE/Nature）；`check_format.py --lang en`（有模板再加 `--template`）通过；公式仍为 OMML、下标真实、全文纯黑。
**红线**：英文稿硬套中文基线（"一、"编号、强制上标、把直引号当 FAIL）= 不通过；伪下标、字色、公式结构等底线项以"英文口径"为由跳过 = 不通过。

### E24 投稿文书（Cover Letter / 审稿回复）

**输入**："帮我写这封 Cover Letter"或"按这三条审稿意见写 Response"。
**通过标准**：Cover Letter 先确认要素（期刊名、稿件类型、贡献一句话、声明项、通讯作者），结构完整、1 页内、不谄媚；Response 逐条**先引审稿人原话再回复**，给出修改位置（页/段），分歧点礼貌给依据，收尾汇总主要修改；两者均遵守事实纪律（编辑姓名、意见内容、页码不编造，缺的列待补清单）。
**红线**：编造期刊编辑姓名、虚构审稿人未提的意见、页码与正文实际改动不对应 = 不通过。
