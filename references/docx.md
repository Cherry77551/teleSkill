# Word 文档处理（.docx）

学术写作的最终交付大多是 `.docx`——参考文献表、润色稿、综述正文。这里给一套可复现的读写与校验纪律。

`.docx` 本质是一个 ZIP 包，内部是 XML。先按任务选路径：

| 任务 | 做法 |
|---|---|
| 新建文档 | 用 `docx`（npm）写脚本生成 |
| 修改现有文档 | `unzip` → 改 `word/document.xml` → `zip` 压回 |
| 读取内容 | `pandoc -t markdown file.docx` |

## 生成

- 用脚本生成，保证可复现；不要手敲格式。
- 页面默认 A4，中文学位论文一般正是 A4；仅在需要时显式改纸张。
- 表格要同时设列宽和每个单元格宽度，单位保持一致，避免在协作文档里错版。
- 标题层级用内置样式，否则自动目录（TOC）抓不到；自定义样式需补 outline 级别。
- 换页用分页符，且必须包在段落里；不要用换行符伪造分段。
- 参考文献表用**悬挂缩进**，不要用空格或制表符硬对齐。

## 编辑现有文档

- 老式 `.doc` 先用 LibreOffice 转成 `.docx` 再处理。
- 先把 XML 拆开，合并被切散的文本片段——同一段文字常被拆成多个 `<w:r>`，直接搜字符串会搜不到。
- **不要重排或美化 XML**，改完原样压回，避免引入无关改动。
- 处理外部来源的文档前，先清理其中的符号链接条目，避免不可信内容。

## 批注与修订

润色与审阅优先用**修订（tracked changes）**和**批注（comments）**交付，而不是静默改稿——让作者能逐条接受或拒绝。

- **修订**：把改动包进 `<w:ins>` / `<w:del>`，带上 id、作者、时间；删除的文字用专用元素，不要直接删掉。
- **批注**：涉及多个互相关联的 XML 文件，建议用现成脚本生成，再在正文插入锚点；否则批注存在但不显示。
- 交付前**按作者名校验**：确认每一处改动都被修订包住，别漏改。

## 交付前渲染看一眼

生成或改完 `.docx`，不要凭空相信它是对的——渲染成图再检查：

```bash
soffice --headless --convert-to pdf out.docx
pdftoppm -jpeg -r 100 out.pdf page
# 逐张看图，确认版式、字体、缩进、分页无误
```

**检查点**：页边距、字号、行距、参考文献悬挂缩进、图表编号与图注、目录页码。

## 依赖

`docx`（npm）、`pandoc`、LibreOffice（`soffice`）、`pdftoppm`（Poppler）。
