# Word 文档处理（.docx）

学术写作的最终交付大多是 `.docx`——参考文献表、润色稿、综述正文。这里给一套可复现的读写与校验纪律。

`.docx` 本质是一个 ZIP 包，内部是 XML。先按任务选路径：

| 任务 | 做法 |
|---|---|
| 新建文档 | 用 `docx`（npm）写脚本生成 |
| 修改现有文档 | `unzip` → 改 `word/document.xml` → `zip` 压回 |
| 读取内容 | `pandoc -t markdown file.docx` |

## 生成

- 用脚本生成，保证可复现；不要手敲格式。
- 页面默认 A4，中文学位论文一般正是 A4；仅在需要时显式改纸张。
- 排版规格（字体字号、字色、标题对齐、目录、标点、公式与符号规范）以 [`manuscript-format.md`](manuscript-format.md)「排版基线」为准，本节只列 Word 实现要点。
- 表格要同时设列宽和每个单元格宽度，单位保持一致，避免在协作文档里错版；**行高、列宽按内容实际情况确定**：长文本列放宽、数字列收窄，行高随内容自适应。表型（三线 / 全线）定义见 [`manuscript-format.md`](manuscript-format.md)「表格」，线宽实现见下方「生成执行清单」第 6 条。
- 标题层级用内置样式，否则自动目录（TOC）抓不到；自定义样式需补 outline 级别。
- 换页用分页符，且必须包在段落里；不要用换行符伪造分段。
- 参考文献表用**悬挂缩进**，不要用空格或制表符硬对齐。
- **字体分开设置**：中文与西文字体分别指定（XML 里 `w:eastAsia` 与 ASCII 字体都要设，否则中文会回退默认字体）；**正文与标题字体分开设**，严禁整篇用一种字体（规格见 [`manuscript-format.md`](manuscript-format.md)「页面与字体」）。
- **正文引用编号用上标**（`w:vertAlign="superscript"`，run 级属性），如"方法[1]"。

- **公式用 OMML 原生公式对象**（`<m:oMath>`）：分数、上下标、根式等结构必须走公式语法，**禁止纯文本平铺、Unicode 字符拼接或截图伪装**；公式行排版为"公式本体居中 + 右对齐制表位放编号 (1)"，编号靠右。
- **公式生成后必须渲染验证**：转 PDF 出图后逐个检查公式显示正确——分数、上下标、根式结构完整，无乱码、无平铺、无错位；有误即修复重新生成再交付。
- **下标/上标用真实格式**：公式与正文符号说明处的下标、上标用 OMML 下标结构或 `w:vertAlign="subscript"`（下标）/ `w:vertAlign="superscript"`（上标）实现；**禁止用 ASCII 下划线 `_` 表示下标**（如文本 x_1 伪下标）。
- **一级标题编号用中文数字**（一、二、三……），二级 1.1、三级 1.1.1。
- **中文正文一律用中文引号""''与全角中文标点**；英文直引号 " ' 不得出现在中文句子里。

## 生成执行清单（写脚本时逐项落实）

写生成脚本前逐条对照，缺一不可：

1. **标题对齐**：一级标题（一、二、三）居中；**二级 1.1、三级 1.1.1 顶格左对齐**，禁止居中。
2. **标题长度**：章节标题控制在 **30 字以内、一行放下**；超长必须精简。
3. **参考文献条目**：文后"参考文献"标题下，每条**独占一行、以 [N] 编号开头**；组成顺序按 GB/T 7714-2015，完整组成表见 [`reference-format.md`](reference-format.md)「每条条目的标准组成」；悬挂缩进（首行顶格、续行缩进 2 字符）。
4. **变量斜体**：正文与表格中的变量（含希腊字母 ω、η、δ 等）用斜体（`<w:i/>`）；数字、单位、下标文字用正体。
5. **下标/上标真实格式**：所有下标用 `w:vertAlign="subscript"` 或 OMML 下标结构；**禁止 `_` 下划线伪下标（含表格符号列）**。
6. **表格线型**：三线表 = 顶线、底线较粗 + 表头下细线，**行间无横线、无竖线**；全线表格 = 全边框。

## 效率纪律（省掉长流程的重复轮次）

生成 10+ 页长文档时，耗时大头是**反复整体重生成 + 逐页全量渲染**，不是文档构建本身。按以下纪律执行：

1. **一次脚本成型**：数据计算 + 文档构建 + `check_format.py` 静态校验合并进**一个脚本一次运行**；脚本报错时先读错误信息定位 XML / OMML 结构问题，修复后重跑一次，不要盲目整篇重新生成。
2. **渲染只抽关键页**：默认不逐页渲染。用 `render_check.ps1 -Docx 论文.docx -FirstPage N -LastPage M` 只出**公式所在页、目录页、首页/尾页**的图；公式修复后只重渲染公式所在页。**全篇逐页渲染仅作为最终交付前的一次性可选动作**，不是默认流程。
3. **减少 Word COM 往返**：多段构建用 python-docx 纯 Python 一次写完，不逐段开 COM 调用；需要更新目录页码等域操作时**只开一次** Office COM 批量处理，不反复启动/退出。
4. **先自查再重跑**：渲染发现公式或版式问题，先在生成脚本中定位对应片段自查（如 OMML 结构、下标包装、制表位），修脚本后再重跑，不用"整篇重跑试错"。

## 公式怎么生成（OMML 技术路径）

规范见 `manuscript-format.md`「公式」小节。禁止把 LaTeX 源码当文本贴进 Word、用 Unicode 画公式或贴截图。**不手写 OMML**——手写 XML 是角标（上下标）结构出错的头号原因，一律改用脚本生成：

1. **LaTeX → OMML（首选，零依赖）**
   - 用 `python scripts/omml.py` 把 LaTeX 转成结构正确的 OMML 片段，例如
     `python scripts/omml.py --display "\frac{\partial f}{\partial x}"` 输出 `<m:oMath…>`；
   - 支持上下标（`x_i`、`x^2`、`x_i^2`、`x^2_i`）、`\frac`、`\sqrt[?]`、`\sum/\prod/\int`、希腊字母、常用运算符，以及 `\bar/\hat/\vec/\dot/\tilde` 等重音；`--dump` 打印解析结构自查；
   - 遇到不支持的结构：扩展 `omml.py`（加一条命令映射）或改走第 2 条的 pandoc，**不要退回手写 XML**。
2. **插入文档（python-docx）**
   - `from omml import insert_omml` → `insert_omml(paragraph, r"\frac{a}{b}", display=True)`；
   - 或自行 `docx.oxml.parse_xml(omml.latex_to_omml(latex))` 后 `paragraph._p.append(el)`；
   - 备用：本地有 pandoc 时，用 `pandoc` 把整篇 Markdown（`$...$`）一次性转 docx，OMML 命名空间与结构同样可靠。
3. **公式行排版（公式居中 + 编号靠右）**
   - 公式段落设两个制表位：中间 `center` 制表位（页面宽一半处）+ 右侧 `right` 制表位（右页边距处）；
   - 段落内容 = `TAB + OMML 公式 + TAB + (编号)`，实现公式居中、编号 (1)(2) 靠右。
4. **先分清是生成错还是渲染错**
   - 生成是否正确用脚本机械判定：`python scripts/check_format.py 论文.docx --strict` 会逐个校验公式的角标结构（`sSub/sSup/sSubSup` 是否缺基/缺子/缺上、公式内有无字面 `_`/`^`）；
   - check 报错 → **生成**问题（改 `omml.py` 调用或生成脚本）；check 通过但渲染图仍异常 → **渲染**问题（换渲染器或补数学字体），不要反复改公式。
5. **渲染验证**
   - 生成后转 PDF 出图，逐个检查公式结构（分数、上下标、根式、编号位置）显示正确；有 Word 时优先用 `render_check.ps1 -UseWord`（Word COM 导出，与 Word 内显示一致），避免 LibreOffice 缺数学字体造成的假失败。

## 编辑现有文档

- 老式 `.doc` 先用 LibreOffice 转成 `.docx` 再处理。
- 先把 XML 拆开，合并被切散的文本片段——同一段文字常被拆成多个 `<w:r>`，直接搜字符串会搜不到。
- **不要重排或美化 XML**，改完原样压回，避免引入无关改动。
- 处理外部来源的文档前，先清理其中的符号链接条目，避免不可信内容。

## 批注与修订

润色与审阅优先用**修订（tracked changes）**和**批注（comments）**交付，而不是静默改稿——让作者能逐条接受或拒绝。

- **修订**：把改动包进 `<w:ins>` / `<w:del>`，带上 id、作者、时间；删除的文字用专用元素，不要直接删掉。
- **批注**：涉及多个互相关联的 XML 文件，建议用现成脚本生成，再在正文插入锚点；否则批注存在但不显示。
- 交付前**按作者名校验**：确认每一处改动都被修订包住，别漏改。

## 交付前渲染看一眼

生成或改完 `.docx`，不要凭空相信它是对的——渲染成图再检查：

```bash
soffice --headless --convert-to pdf out.docx
pdftoppm -jpeg -r 100 out.pdf page
# 逐张看图，确认版式、字体、缩进、分页无误
```

一键脚本见 [`../scripts/render_check.ps1`](../scripts/render_check.ps1)：`.\render_check.ps1 -Docx out.docx` 自动转 PDF 出图（默认只渲染第 1 页）；加 `-FirstPage N -LastPage M` 只渲染指定页段（公式页 / 目录页 / 首尾页须显式传页范围）；`-All` 才全量渲染（仅交付前一次性可选）。

**注意：这里的 PDF 和逐页图片只是渲染校验用的中间产物**，输出到 `.temp/` 目录；校验完成后与交付无关——**最终交付只包含用户选定的格式**（用户选了 Word 就只交付 `.docx`，不得把 PDF 一并交付）。

**检查点**：页边距、**正文字体字号 = 用户确认的规格**（标题黑体、正文宋体，未整篇混用）、**全文纯黑字色**、**题目与章标题居中**、**目录独占一页**、行距、**正文引用编号右上角上标**、**公式为原生公式对象、编号靠右且渲染正确**、**符号下标为真实格式（无 x_1 式伪下标）**、**表格行列宽高按内容确定、美观**、**表型与用户确认一致（默认全线表格）**、**一级标题中文编号**、**正文中文引号与中文标点**、参考文献悬挂缩进、图表编号与图注、目录页码。**逐项核对，任何一项不符即返工重排后再交付。**

## 依赖

`docx`（npm）、`pandoc`、LibreOffice（`soffice`）、`pdftoppm`（Poppler）。
