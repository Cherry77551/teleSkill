# 英文论文（SCI / 国际期刊投稿）

中文流程走到英文投稿时的分支模块：英文论文正文、排版、Cover Letter、审稿意见回复（Response to Reviewers）。文献梳理、数据图表、参考文献排版、迭代改稿等共享流程**不变**（`format_refs.py` 已支持 `--format apa|ieee|nature`），只有**排版基线、语言规范、投稿文书**按本文件执行。

## 什么时候用

- 写英文论文 / SCI / EI 投稿正文 → 本模块 + [`manuscript-format.md`](manuscript-format.md) 共用（排版按本文件英文基线）
- Cover Letter（投稿信）→ 本模块
- Response to Reviewers（逐条回复审稿意见）→ 本模块 + [`revision.md`](revision.md)（修订闭环共用）
- 英文润色 / 降 AI 率 → 本文件「英文语言规范」+ [`polish.md`](polish.md)（流程共用）
- 中文论文 → 跳过本模块，一切按中文基线

## 语言判定（不新增提问）

**不设"语言题"**，按信号判定，信号全部来自用户消息与现有确认项：

| 优先级 | 信号 | 判定 |
|---|---|---|
| 1 | 用户明说"英文写 / in English / SCI 投稿" | 英文 |
| 2 | 提供英文期刊模板、指明目标国际期刊（IEEE / Elsevier / Springer / Nature 系） | 英文 |
| 3 | 参考文献格式选 APA / IEEE / Nature | 倾向英文；选 GB/T 7714 → 中文 |
| 4 | 仅英文摘要、资料全为英文文献 | 倾向英文（拿不准时只确认期刊，不确认语言） |
| 5 | 无任何信号 | **中文** |

- 判定**中文** → 不询问、不出现在选择题与汇总复述中（默认中文不呈现）。
- 判定**英文** → **不单独发问**，在汇总复述中写明"**本次按英文写作执行**"并附一句判定依据（如"依据：检测到 IEEE 期刊模板"），随全部要求一起等用户点头；用户在点头前说"我要中文"即改判重来。

## 英文排版基线

目标期刊有投稿指南或模板时**以其为准**（模板套用流程见 [`template-reuse.md`](template-reuse.md)）；没有时用下表。与中文基线（[`manuscript-format.md`](manuscript-format.md)）的差异项：

| 项 | 英文默认 | 中文默认（对照） |
|---|---|---|
| 正文字体 | **Times New Roman 12 pt** | 宋体小四 |
| 标题编号 | **数字制：1、1.1、1.1.1**（如 "1 Introduction"） | 一、二、三 + 1.1 |
| 标题字体 | 与正文同族，**加粗分级**（或全大写一级） | 黑体 |
| 标点 | **英文标点**，直引号 " ' 合法 | 中文全角标点，禁直引号 |
| 交叉引用 | **Figure 1 / Table 1 / Eq. (1)**（缩写 Fig. 1 首次出现给全称） | 图 1 / 表 1 / 式(1) |
| 段落 | 首行缩进 0.5 in（或按模板）；行距按期刊（双倍 / 1.5） | 首行缩进 2 字符、1.5 倍 |
| 正文引用 | 按格式：APA `(Author, 2020)` 行内；IEEE `[1]` 行内或上标，**不强制上标** | 右上角上标强制 |

**不变项**：全文纯黑、公式 OMML 原生对象且编号居右、真实下标（禁 `x_1`）、参考文献一条一行悬挂缩进、目录独占一页、表格按用户确认的表型、变量斜体。数字与单位间加空格、缩写首次出现给全称。

## 英文语言规范（降 AI 率）

原则与 [`human-writing.md`](human-writing.md) 相同：**有起伏、有变化、不可预测**；段长句长量化标准（相邻段差 ≥30%、三档交替）照用，`check_style.py` 同样适用。英文专属规则：

**AI 高频词替换**（能删就删，删不掉换自然表达；替换词本身也不许高频重复）：

| AI 高频写法 | 处理 |
|---|---|
| Additionally / Moreover / Furthermore | 删，或改句式直接续接 |
| It is worth noting that / It should be noted that | 直接陈述 |
| plays a crucial role in | is key to / drives |
| delve into / comprehensive investigation | examine / study |
| leverage / utilize | use |
| In conclusion / Overall | 删总结句，让结构不"标准" |
| significant（无统计支撑时） | 给效应量 / 统计表述，或删 |

**句式与时态**：

- 时态按学术惯例：方法与结果用过去时（"We measured…"），结论与普遍事实用现在时；文献综述按引用内容定。
- 适度主动语态（"We propose…"），避免连续被动堆叠；一个段落里主句结构不重复。
- 句长错落：每段长句（≥25 词）与短句（≤10 词）并存；不连续同长。

## 投稿文书

### Cover Letter（投稿信，1 页内）

生成前确认要素：期刊名与主编称谓、稿件标题与类型（Article / Letter / Review）、一句话核心贡献、为何适合该刊（点名期刊定位，**不谄媚**）、声明项（原创性 / 未一稿多投 / 无利益冲突 / 全体作者同意）、推荐审稿人（可选）、通讯作者信息。

结构：① 收件人与稿件信息 ② 核心贡献与适配理由（2~3 句）③ 声明项 ④ 通讯作者落款。**主编姓名按用户提供或留 `[待补]`，不编造。**

### Response to Reviewers（逐条回复）

流程与 [`revision.md`](revision.md) 五步共用（收集意见 → 映射改动点 → 执行 → 复核 → 交付），英文版补充：

1. **逐条编号**：Reviewer #1 Comment 1、Comment 2……**先引审稿人原话**（斜体或引用块），再回复。
2. **回复结构**：Response（改了什么、为什么）→ Changes made（改后文字 + 页码/段落位置）。
3. **语气**：礼貌但不过度道歉；不认同的意见**礼貌给出依据反驳**，不硬顶也不全盘接受。
4. **收尾**：汇总主要修改清单，感谢编辑与审稿人。
5. 红线：**不虚构审稿人未提的意见、不编造页码与修改内容**；修改与正文实际改动一一对应。

## 交付前校验

运行 `python scripts/check_format.py 论文.docx --lang en --strict`（提供了模板再加 `--template 模板.docx`）：英文口径自动切换——英文直引号合法、一级标题按数字编号、目录认 Contents、参考文献认 References、交叉引用认 Figure/Table/Eq.、正文引用不强制上标；公式 OMML、伪下标、字色、页边距、表格线型等学术底线项**照常校验**。渲染抽样口径不变（公式页 / 目录页 / 首尾页）。

## 红线

- **判英文后未在汇总复述中呈现即动笔 = 不合格**（语言是重大决策，必须过点头关）。
- **无任何英文信号却判英文 = 不合格**（应默认中文）。
- **英文稿硬套中文基线**（宋体小四、"一、"编号、强制上标、把直引号当错）= 不合格。
- Cover Letter / Response 中**编造期刊编辑、审稿意见、页码位置 = 不合格**。
- 事实纪律、唯一交付格式、敏感信息保密等共享纪律全部照常适用。

## 产出与去向

英文论文 docx（或用户确认的格式）+ 按需的 Cover Letter / Response to Reviewers 独立文档；排版执行见 [`manuscript-format.md`](manuscript-format.md)（差异项以本文件为准）；引用排版见 [`reference-format.md`](reference-format.md)；改稿闭环见 [`revision.md`](revision.md)。
