# 迭代改稿（修订稿）

导师 / 审稿人意见驱动的改稿，用"修订"闭环交付，让作者逐条接受或拒绝。触发场景：用户说"老师提了意见，帮我改改"、"按审稿意见修改"、"改一稿"。

## 五步流程

### 1. 收集意见

接收多条意见（粘贴文本、逐条列表、批注截图均可），先**去重归类**：内容类（结论/方法）、结构类（章节组织）、语言类、格式类。

### 2. 意见 → 改动点映射

把每条意见**定位到具体章节/段落**，产出"意见 → 改动点"对照表：

> | 意见 | 位置 | 改动点 |
> |---|---|---|
> | 第三章方法描述含糊 | 3.2 节 | 补充公式推导，重写 3.2.1 |

**先列给用户确认改动范围，用户点头再动手**——不擅自扩大改动面。

### 3. 执行修改 + 连带更新（关键）

改正文只是开始，**凡是受影响的文档部件必须同步更新**：

- **结论 / 观点变了** → 摘要、结论章节同步改写；
- **章节增删 / 改名** → 目录页码与章节名、章节编号重排；
- **参考文献增删** → 文后条目重排 + **正文上标编号全文重新编号**；
- **图 / 表 / 公式增删** → 图题表号式编号重排 + 正文所有交叉引用（"图 N / 表 N / 式(N)"）同步修正。

### 4. 复核

改完自动校验：

- `python scripts/check_format.py 论文.docx`——排版 + **交叉引用一致性**；
- `python scripts/check_style.py 正文.md/.docx`——段长错落；
- 渲染成图复核**被改动的页面**；
- 被重写的段落做一次"新读者"可读性检查（见 `polish.md`）。

### 5. 交付修订稿

- 用 **Word 修订（tracked changes）** 交付，作者可逐条接受/拒绝（技术见 `docx.md`）；
- 或交付"改后 + 为什么改"的批注对照；
- 附"意见 → 处理结果"回执表，逐条说明采纳/未采纳及原因。

## 红线

- **只改要改的**：不顺手改无关表述、不动数据与结论（除非意见明确要求）。
- **意见含糊先问**：定位不了的意见先澄清，不猜。
- **不产生新占位**：修改后不得遗留 `[待补来源]`、`此处补充` 等占位；缺的料单列清单。
- 修订稿依旧遵守语言规范（`human-writing.md`）与排版硬约束。
